### สไลด์ที่ 2: ความเป็นมาของโครงงาน (Background & Motivation)
- **หัวข้อตามเกณฑ์:** หัวข้อที่ 2
- **ชื่อสไลด์:** ความเป็นมาของโครงงาน (Background & Motivation)
- **ผู้รับผิดชอบบรรยาย:** นายปฏิภาณ พิพัฒน์พิทยากุล
- **เวลาโดยประมาณ:** 1.5 นาที
- **เนื้อหาบนสไลด์:**
  - **ปัญหาในปัจจุบัน (Problem Statement):**
    - ไฟล์ขยะสะสมในคอมพิวเตอร์: โฟลเดอร์ Downloads และ Desktop รก ไม่เป็นระเบียบ
    - ความเสี่ยงด้านความเป็นส่วนตัว: โปรแกรมจัดการไฟล์ทั่วไปมักส่ง Telemetry หรือรายชื่อไฟล์ขึ้นคลาวด์ภายนอก
    - ผู้ใช้ไม่กล้าลบไฟล์: กลัวข้อมูลสำคัญสูญหาย เพราะขาดระบบกู้คืน (Undo) ที่เชื่อถือได้
    - เสียเวลาจัดระเบียบด้วยมือ: ไม่มีระบบอัตโนมัติคัดแยกประเภทหรือวันที่ถ่ายภาพ
  - **แรงจูงใจในการพัฒนา (Motivation & Solution):**
    - ยึดสถาปัตยกรรมแบบ **Local-First**: ข้อมูลประมวลผลในเครื่อง 100% ไม่มี Telemetry
    - มั่นใจด้วย **Safe Cleanup**: ลบไฟล์ผ่าน Recycle Bin เสมอ และบล็อกการแตะต้องโฟลเดอร์ระบบ
    - มี **Persistent Undo**: เก็บประวัติลง SQLite ย้อนกลับการย้ายไฟล์ได้แม้ปิดโปรแกรมไปแล้ว
- **บทพูดนำเสนอ (Speaker Script):**
  > "สำหรับความเป็นมาของโครงงานนะครับ ในปัจจุบันผู้ใช้งานคอมพิวเตอร์มักประสบปัญหาพื้นที่ดิสก์เต็ม มีไฟล์ซ้ำซ้อน และโฟลเดอร์ดาวน์โหลดรกไม่เป็นระเบียบ
  > แต่โปรแกรมจัดการไฟล์ส่วนใหญ่ในท้องตลาด มักมีข้อจำกัดเรื่องความเป็นส่วนตัว เพราะมีการส่งข้อมูลการสแกนและรายชื่อไฟล์ขึ้นไปยังคลาวด์ หรือบังคับต่อเน็ตตลอดเวลา
  > อีกทั้งผู้ใช้ทั่วไปมักไม่กล้าลบหรือจัดระเบียบไฟล์ เพราะกลัวข้อมูลสำคัญสูญหาย กลุ่มของพวกเราจึงพัฒนา **Smart File Manager Pro** ขึ้นมา โดยยึดหลัก **Local-First** ทำงานในเครื่อง 100% ปลอดภัย ไม่ส่งข้อมูลออกภายนอก พร้อมระบบ Undo ที่บันทึกลงฐานข้อมูล กู้คืนการกระทำได้จริงครับ"

### สไลด์ที่ 3: วัตถุประสงค์ของโครงงาน (Project Objectives)

- **ผู้รับผิดชอบบรรยาย:** นายปฏิภาณ พิพัฒน์พิทยากุล

  > ข้อสอง เพื่อสร้างระบบจัดระเบียบไฟล์และค้นหาไฟล์ซ้ำที่มีประสิทธิภาพสูง มีระบบ Hash Cache ช่วยประหยัดเวลาสแกนดิสก์ และมีระบบ Undo ที่เก็บประวัติลงฐานข้อมูล SQLite

### สไลด์ที่ 4: ขีดความสามารถของโครงงาน (Features Overview)
- **หัวข้อตามเกณฑ์:** หัวข้อที่ 4
- **ชื่อสไลด์:** ขีดความสามารถของโครงงาน (7 Features Overview)
- **ผู้รับผิดชอบบรรยาย:** นายณัฐพงศ์ เหินหาว
- **เวลาโดยประมาณ:** 1.5 นาที
- **เนื้อหาบนสไลด์:**
  - **1. Dashboard:** สรุปสุขภาพไฟล์, วงแหวนคะแนน Tidiness Score (0–100), กราฟ Sparklines CPU/RAM/Network
  - **2. File Organizer:** จัดระเบียบตามประเภท, ตามเดือน, หรือ Custom Rules พร้อม Auto Preview แสดงตัวอย่าง
  - **3. Duplicate Finder:** สแกน 3 ขั้นตอน (ขนาด ➔ Partial Hash ➔ SHA-256) พร้อม Hash Cache
  - **4. Similar Photos:** ค้นหารูปถ่ายต่อเนื่องหรือภาพที่คล้ายกันด้วย Perceptual Hashing 3 รูปแบบ พร้อมแสดงภาพย่อ
  - **5. Safe Cleanup:** ล้างไฟล์ขยะและโฟลเดอร์ว่างอย่างปลอดภัย โดยส่งเข้า OS Recycle Bin เท่านั้น
  - **6. Bulk Renamer & Backup:** เปลี่ยนชื่อไฟล์เป็นชุดพร้อมตรวจจับชื่อชนกัน และระบบสำรองข้อมูลแบบทางเดียว
  - **7. UI & Themes:** รองรับ 6 ธีมสี (เช่น Lavender, Obsidian, Deep Blue), ปรับขนาดฟอนต์ได้ และรองรับภาษาไทย 100%
- **บทพูดนำเสนอ (Speaker Script):**
  > "กระผม ณัฐพงศ์ เหินหาว ขออธิบายขีดความสามารถของระบบครับ
  > Smart File Manager Pro มาพร้อม 7 เครื่องมือหลักในแถบเมนูด้านข้าง:
  > หน้า Dashboard แสดงสถานะทรัพยากรสดและคะแนนความเป็นระเบียบ, หน้า File Organizer จัดไฟล์ตามประเภทหรือเดือนพร้อมพรีวิวก่อนย้ายจริง, หน้า Duplicate Finder และ Similar Photos ช่วยหาไฟล์ซ้ำและภาพถ่ายคล้ายกันพร้อมแสดงภาพย่อ, หน้า Cleanup ส่งไฟล์ขยะลงถังรีไซเคิลอย่างปลอดภัย, หน้า Bulk Renamer และ Backup ช่วยเปลี่ยนชื่อและสำรองไฟล์แบบทางเดียว และระบบสามารถสลับธีมได้ 6 รูปแบบพร้อมรองรับภาษาไทย 100% ครับ"

### สไลด์ที่ 7: โครงสร้างของโครงงานในภาพรวม (Overall Architecture)
- **หัวข้อตามเกณฑ์:** หัวข้อที่ 6
- **ชื่อสไลด์:** สถาปัตยกรรม 3 ชั้น (3-Tier Local-First Architecture)
- **ผู้รับผิดชอบบรรยาย:** นายปฏิภาณ พิพัฒน์พิทยากุล
- **เวลาโดยประมาณ:** 1.5 นาที
- **เนื้อหาบนสไลด์:**
  - **1. Presentation Layer (ส่วนติดต่อผู้ใช้):**
    - PySide6 (Qt for Python), การ์ด Responsive, ระบบ Dynamic Theme, และระบบแปลภาษา Real-time
  - **2. Application Services (การประมวลผลระบบ):**
    - QThread Concurrency: รันการสแกนและคำนวณเบื้องหลัง หน้าต่างไม่ค้าง
    - Streaming SHA-256 Engine: แบ่งอ่าน Buffer 1MB ทำความเร็วสูง ~1.8 GB/s
    - Safety Guard: ฟังก์ชัน `is_protected()` ป้องกันโฟลเดอร์ระบบ (`C:\Windows`, `/System`, `/usr`)
  - **3. Data & Platform Layer (การจัดเก็บและระบบปฏิบัติการ):**
    - Local SQLite (`sfm.db`): จัดเก็บประวัติ Undo, Logs, และ Hash Cache
    - OS Shell Integration: ลบไฟล์ผ่าน `send2trash` (เข้า Recycle Bin)
    - Supabase Auth: ยืนยันตัวตนคลาวด์ทางเลือก (เก็บเฉพาะ User ID, ไม่เก็บไฟล์)
- **บทพูดนำเสนอ (Speaker Script):**
  > "โครงสร้างของโครงงานถูกออกแบบตามสถาปัตยกรรม 3 ชั้น (3-Tier Local-First Architecture) ครับ:
  > ชั้นบนสุดคือ Presentation Layer ใช้ PySide6 จัดการ UI และภาษาไทย
  > ชั้นกลางคือ Application Services ใช้ระบบมัลติเธรด QThread แยกงานสแกนไฟล์เบื้องหลังเพื่อไม่ให้หน้าจอค้าง มีระบบคำนวณ Hash ความเร็วสูงถึง 1.8 GB/s และระบบตรวจจับ Path Traversal ป้องกันโฟลเดอร์ระบบ
  > และชั้นล่างสุดคือ Data Layer เก็บประวัติการทำงานและแคชลงใน SQLite ภายในเครื่อง (`sfm.db`) ข้อมูลไฟล์ทั้งหมดไม่เคยส่งออกนอกเครื่องครับ"

### สไลด์ที่ 9: อธิบายโค้ดส่วน Core Engine & SQLite Persistence
- **หัวข้อตามเกณฑ์:** หัวข้อที่ 7 (ต่อ)
- **ชื่อสไลด์:** อธิบายโค้ดส่วน Core Engine & SQLite Persistence
- **ผู้รับผิดชอบบรรยาย:** นายทัตพร สีโส
- **เวลาโดยประมาณ:** 1.5 นาที
- **เนื้อหาบนสไลด์:**
  - **`core.py` (Pure Python Engine):**
    - `scan_directory()`: ท่องไดเรกทอรีแบบ Generator ข้ามไฟล์ระบบอย่างปลอดภัย
    - `find_duplicates()`: สแกน 3 ขั้นตอน (เปรียบเทียบขนาด ➔ Partial Hash ➔ Full SHA-256)
    - `organize_files()`: จัดระเบียบไฟล์พร้อมตรวจจับชื่อชนกันด้วย `unique_dest()`
    - `undo_move()`: ดึงรายการย้ายจากฐานข้อมูลเพื่อคืนไฟล์กลับตำแหน่งเดิมอย่างแม่นยำ
  - **`db.py` (SQLite Persistence):**
    - ตาราง `undo_batches` และ `undo_moves` รองรับ Undo ข้ามการเปิดปิดโปรแกรม
    - ตาราง `hash_cache` บันทึกค่าแฮชคู่กับ File Size และ mtime ทำให้สแกนซ้ำเร็วขึ้น 3.6 เท่า
    - ใช้ Parameterized Queries (`?`) ทุกจุด ป้องกันช่องโหว่ SQL Injection
- **บทพูดนำเสนอ (Speaker Script):**
  > "กระผม ทัตพร สีโส ขออธิบายโค้ดส่วน Core และฐานข้อมูลครับ
  > ใน `core.py` เป็น Pure Python Engine ไม่พึ่งพา UI มีฟังก์ชันค้นหาไฟล์ซ้ำแบบ 3 ขั้นตอนเพื่อประหยัดเวลา และมีระบบตรวจจับชื่อชนกันอัตโนมัติ
  > ใน `db.py` ใช้ SQLite มาตรฐาน เก็บตาราง Undo ทำให้สามารถย้อนกลับการจัดไฟล์ข้ามวันได้ และมีระบบ Hash Cache ที่จำค่าแฮชของไฟล์เดิม ทำให้เมื่อสแกนซ้ำจะเร็วขึ้นถึง 3.6 เท่า โดยคำสั่ง SQL ทุกตัวใช้ Parameterized Query เพื่อความปลอดภัยสูงสุดครับ"

## 3. แนวทางการตอบคำถามที่อาจารย์น่าจะถาม (Anticipated Q&A)

### Q1: ทำไมถึงเลือกใช้แนวทาง Local-First แทนที่จะทำเป็นเว็บแอปหรือเก็บข้อมูลบน Cloud?
- **แนวทางการตอบ:** "เนื่องจากไฟล์ของผู้ใช้เป็นข้อมูลส่วนบุคคลที่มีความละเอียดอ่อนสูง เช่น เอกสารสำคัญหรือรูปภาพส่วนตัว หากอัปโหลดขึ้น Cloud จะมีความเสี่ยงเรื่องความเป็นส่วนตัวและค่าใช้จ่ายของเซิร์ฟเวอร์ การใช้สถาปัตยกรรม Local-First จึงตอบโจทย์ความปลอดภัยสูงสุด ทำงานได้แม้ออฟไลน์ และมีความเร็วในการจัดการไฟล์บนดิสก์ที่เหนือกว่าเว็บแอปพลิเคชันอย่างมากครับ"

### Q2: Duplicate Finder ป้องกันการลบไฟล์ผิดพลาดได้อย่างไร?
- **แนวทางการตอบ:** "เราใช้การเปรียบเทียบ 3 ชั้นครับ คือเริ่มจากเทียบขนาดไฟล์ก่อน หากเท่ากันจะคำนวณ Partial Hash 8KB แรก และหากยังเท่ากันอีกจึงคำนวณ Full SHA-256 เพื่อความแม่นยำ 100% นอกจากนี้โปรแกรมจะไม่เลือกไฟล์ต้นฉบับไว้ และเมื่อผู้ใช้สั่งลบ ไฟล์จะถูกส่งเข้าถังรีไซเคิลของระบบ (Recycle Bin) ผ่านไลบรารี `send2trash` เสมอ ไม่มีการลบถาวรทันที จึงสามารถกู้คืนได้เสมอครับ"

### Q3: ระบบ Undo ข้ามการเปิดปิดโปรแกรมทำงานอย่างไร?
- **แนวทางการตอบ:** "เราใช้ฐานข้อมูล SQLite ภายในเครื่อง (`~/.smart_file_manager_pro/sfm.db`) โดยมีตาราง `undo_batches` สำหรับเก็บรอบการย้ายไฟล์ และ `undo_moves` สำหรับเก็บพาธต้นทางและปลายทาง เมื่อผู้ใช้ปิดโปรแกรมและเปิดใหม่ ข้อมูลใน SQLite จะไม่หาย ทำให้สามารถคลิก Undo เพื่อย้ายไฟล์กลับคืนตำแหน่งเดิมได้อย่างสมบูรณ์ครับ"

### Q4: การทำงานบน GitHub มีการแบ่งงานกันอย่างไร และมั่นใจได้อย่างไรว่าโค้ดไม่มีข้อผิดพลาด?
- **แนวทางการตอบ:** "พวกเราใช้ Gitflow โดยแบ่งเป็นกิ่ง `team/dev`, `team/ui-design`, `team/tester`, และ `team/docs` โดยไม่มีใครทำงานตรงบนกิ่ง `main` ครับ ทุกการเปลี่ยนแปลงจะต้องส่งเป็น Pull Request และต้องผ่านการทดสอบอัตโนมัติ 58 รายการบน GitHub Actions CI บนทั้งระบบปฏิบัติการ Ubuntu และ Windows ก่อนจึงจะอนุญาตให้ Merge เข้าสู่กิ่ง `develop` และ `main` ได้ครับ"
